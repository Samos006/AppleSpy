# AppleSpy 

**AppleSpy** — Telegram-бот и мини-приложение для отслеживания цен и наличия товаров в [Золотом Яблоке](https://goldapple.ru/).

Проект помогает следить за изменениями стоимости товаров, сохранять историю цен и получать уведомления о важных изменениях.

**Ссылки:**
-  Telegram-бот: [@AppleSpyBot](https://t.me/AppleSpyBot)
-  Мини-приложение: [applespy.panoff.dev](https://applespy.panoff.dev)

## Возможности

- **Отслеживание цен** — автоматическая проверка стоимости товаров.
- **Мониторинг наличия** — отслеживание изменений доступности товаров.
- **Уведомления в Telegram** — получение сообщений об изменениях.
- **История цен** — сохранение истории изменения стоимости товаров.
- **Целевая цена** — настройка уведомлений при достижении определённой стоимости.
- **Мини-приложение** — просмотр отслеживаемых товаров, истории изменений и настроек.
- **Управление подписками** — добавление товаров по ссылке и настройка отслеживания.

## Как работает проект

1. Пользователь отправляет боту ссылку на товар в Золотом Яблоке.
2. Приложение извлекает идентификатор товара и получает информацию о его цене и наличии.
3. Фоновый обработчик периодически проверяет отслеживаемые товары.
4. Система сравнивает новые данные с предыдущим состоянием и сохраняет историю изменений.
5. При наступлении заданного условия пользователь получает уведомление в Telegram.
6. В мини-приложении можно просматривать отслеживаемые товары, историю цен и управлять настройками.

Для уменьшения количества ложных уведомлений изменения наличия подтверждаются несколькими последовательными проверками. Повторные одинаковые уведомления ограничиваются временным интервалом.

## Локальный запуск

### Требования

- Python
- Node.js и npm
- PostgreSQL
- Telegram Bot Token

Для получения данных о товарах также используется Playwright с Chromium.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Samos006/AppleSpy.git
cd AppleSpy
```

### 2. Настройка backend

```bash
cd backend

python -m venv .venv
```

Активация виртуального окружения:

**Linux / macOS**
```bash
source .venv/bin/activate
```

**Windows**
```bash
.venv\Scripts\activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
pip install -r requirements-browser.txt
playwright install chromium
```

### 3. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example` и укажите необходимые параметры:

```env
BOT_TOKEN=your_telegram_bot_token
WEBAPP_URL=https://your-webapp-url
BOT_MODE=polling

GA_CITY_ID=your_city_id
GA_REGION_ID=your_region_id
GA_PROXIES=

GA_BROWSER_FALLBACK=true
```

Также настройте подключение к PostgreSQL и остальные параметры приложения, предусмотренные конфигурацией проекта.

Не публикуйте токены и другие секретные данные в репозитории.

### 4. Подготовка базы данных

Примените миграции:

```bash
alembic upgrade head
```

Убедитесь, что PostgreSQL запущен и параметры подключения указаны правильно.

### 5. Запуск backend

Из директории `backend` выполните:

```bash
uvicorn app.main:app --reload
```

### 6. Запуск frontend

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Для локального запуска PostgreSQL, API, бота и фонового обработчика также предусмотрен `docker-compose.yml`.

> **Примечание:** для полноценной работы необходимо отдельно запустить Telegram-бота и фоновый обработчик, настроить переменные окружения и обеспечить доступ к API Золотого Яблока.

## Структура данных

В проекте используются следующие основные сущности:

- `users` — пользователи Telegram.
- `products` — информация о товарах и их текущем состоянии.
- `price_points` — история изменения цен.
- `watches` — подписки пользователей на товары и настройки отслеживания.
- `events` — зафиксированные изменения, используемые для уведомлений и отображения истории событий.

## Особенности реализации

- Асинхронная работа с базой данных и HTTP-запросами.
- Разделение API, бизнес-логики, фоновых задач и Telegram-бота.
- Проверка подлинности данных Telegram Mini Apps.
- Обработка ошибок при получении данных о товарах.
- Повторные проверки для подтверждения изменений наличия.
- Сохранение истории только при изменении цены.
- Ограничение частоты повторных уведомлений.
- Использование Playwright для прохождения проверки браузерной сессии при получении данных.

## Развёртывание

Для production-развёртывания предусмотрены Nginx, Uvicorn, systemd и PostgreSQL. Конфигурация и скрипты обновления находятся в директории `deploy/`.
